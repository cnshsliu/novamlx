# Peer 与 tknet 的接口一致性 — 需求说明书

**日期：** 2026-10-14
**状态：** 已完成（2026-10-14）。Peer 与 tknet 已对齐；测试存量可直接清掉后重上架。
**依据：** `docs/superpowers/specs/2026-10-11-tknet-peer-gateway-design.md` 描述现在的网关。本文不改那份已经落地的行为，只规定下一步必须补上的一致性。

## 目标

一个 Peer 可以同时提供多种 API 接口。每一种接口下面可以有多个模型。

同一个模型只属于一种接口。上游模型、Peer、tknet 请求、tknet 供应商列表这四处，对这个模型使用同一份接口约定。

```
一个 Peer
  对话接口 → 模型 A、模型 B
  图像生成接口 → 模型 C
  图像编辑接口 → 模型 D
  向量接口 → 模型 E
```

## 约定挂在模型上

约定的单位是一个模型，不是整个 Peer。

在 Peer 里，一个模型是一个池子。池子上要写明它的接口。在 tknet 上，一条供应对应这个池子，并带同一份接口。

一份接口是一组固定的调用，而不是单独一条路径。现在已有的接口是：

| 接口 | 路径 |
|---|---|
| 对话 | `POST /v1/chat/completions` |
| 图像生成 | `POST /v1/images/generations` |
| 图像编辑 | `POST /v1/images/edits` |
| 语音合成 | `POST /v1/audio/speech` |
| 语音识别 | `POST /v1/audio/transcriptions` |
| 向量 | `POST /v1/embeddings` |
| 决策 | `POST /v1/decisions` |
| 去背景 | `POST /v1/images/background-removals` |

说明（2026-10-14 已定）：

- **不做** `/v1/images/variations`。业界几乎只有 `dall-e-2` 遗产支持，多数供应商和网关不提供；本产品也不再挂这条路径。
- **图像生成**与**图像编辑**是两种独立接口，不是「图像」整包。一个池子只能标其中一种。只支持文生图的模型挂图像生成；支持图生图/局部编辑的模型挂图像编辑。

同一个模型名不能同时属于两种接口。不同的模型名可以属于同一种接口，这就是「一种接口下面多个模型」。

## 四处各守什么

**上游模型。** 它实际会做的事必须和约定一致。约定由登记这个模型的人写下，或者在成员是 NovaMLX、模型类型已知时由 `SupplyAPI` 生成。运行时不探测上游支持哪些路径。上游不认某次合法请求时，按现在的规则把 4xx 交回调用方。

**Peer。** 池子带有接口。请求的路径必须落在这个接口里，Peer 才转发，并把 `model` 改成该成员的上游模型名，路径保持不变。路径不在接口里时，Peer 直接拒绝，不把请求打到上游。本机 `6600` 和从隧道进来的请求用同一条规则。本机端口与能力上报都**不再**暴露 `/v1/images/variations`。

**tknet 请求。** 只按这个模型的接口把请求送给对应的 Peer。隧道帧里要能表达路径。没有路径的旧帧只当作对话，并且只发给约定为对话的模型。

**供应商列表。** 只展示这个模型那一份接口里的路径。列表上的接口来自池子，不能在上架时另选一个和池子无关的类型。一种接口有多条路径时，列表列出全部路径（当前表里多数接口只有一条路径）。

## 现在对不上的地方

这些是要改掉的现状，不是目标的一部分。

- 池子没有接口字段。`6600` 上的每条路径对每个池子都开着。向量模型被拿去打 `/v1/chat/completions` 时，Peer 会照样转发。
- 隧道帧只有模型名和正文，没有路径。tknet 转给 Peer 的请求固定按对话处理。
- 供应商列表上的接口是上架表单里手选的。Peer 不上报池子的接口，两边没有核对。
- 活跃供应的唯一键是 `(peer, 模型名)`。同名不能挂两条。这和「一个模型只属于一种接口」一致，保留。
- 本机端口与旧设计仍可能列出 `/v1/images/variations`；按本文应去掉。

## 存量数据

现有上架与池子数据均为测试用途。落地时**可以直接删除**相关测试供应/配置，不必做接口字段迁移或回填。以 Peer 池子上的接口字段为真相源，重新登记即可。

## 怎样算做完

1. 一个 Peer 可以同时挂对话模型和向量模型。对话模型有两个时，两个都只走对话路径。
2. 对向量模型发送 `/v1/chat/completions`，Peer 拒绝，上游收不到这次请求。
3. tknet 把一次向量请求送到这个 Peer 时，Peer 收到的是 `/v1/embeddings`，不是对话。
4. 供应商页面上这个模型列出的路径，和池子的接口、以及 tknet 实际会发送的路径，是同一组。
5. 上架时不能把一个向量池子标成对话。
6. 图像生成池子只接受 `/v1/images/generations`；图像编辑池子只接受 `/v1/images/edits`；对图像生成池子打 edits（或反过来）被 Peer 拒绝。
7. `/v1/images/variations` 在本机端口、能力上报、供应商列表中均不出现；打到该路径返回 404（或不提供该路由）。

## 不做

- 不在每次请求时探测上游支持哪些路径。
- 不把一个模型同时标成两种接口。
- 不限制一个 Peer 只能提供一种接口。
- 不改挑选方式、故障转移和密钥存放。路径不对的请求在挑选之前就拒绝。
- 不提供 `/v1/images/variations`。
- 不把「图像」做成包含多条路径的整包接口。
