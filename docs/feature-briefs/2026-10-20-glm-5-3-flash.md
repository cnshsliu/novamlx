# GLM-5.3-Flash（仅文本）

## Title

GLM-5.3-Flash — Apple Silicon 上的本地文本模型（`glm5_next`）

## One-line pitch

Run GLM-5.3-Flash locally on Apple Silicon — text chat only, from a catalogued MLX quant.

在 Apple Silicon 上本地运行 GLM-5.3-Flash：仅文本对话，从目录里的 MLX 量化加载。

## Who it is for / when to care

给已经在 Mac 上用 NovaMLX 跑本地模型、并希望加载 GLM-5.3-Flash 文本量化的人。统一内存大约 256 GB 时用 mlx-community 4-bit；大约 128 GB 时用 TensorFold 混合 2-bit。需要图像或视频时，这次发布不适用。

For people running NovaMLX on a Mac who want GLM-5.3-Flash as a local text model. Use the 4-bit quant around 256 GB of unified memory, or the hybrid 2-bit quant around 128 GB. This ship does not load vision.

## What shipped (user-visible behavior)

NovaMLX 可以按文本 LLM 下载并加载两条 preview 量化。`model_type` 为 `glm5_next`（文本 `glm5_next_text`）：混合 linear attention 与 sparse MLA、mHC、288 路专家 MoE。实现在 `Sources/NovaMLXEngine/Models/Glm5NextModel.swift`，注册名 `glm5_next` 与 `glm5_next_text`。`mlx-swift-lm` 的 `glm4` / `glm4_moe` 不覆盖这个架构。

| 仓库 | 磁盘（目录标注） | 目录建议统一内存 | 索引 `metadata.total_size` |
| --- | --- | --- | --- |
| `mlx-community/GLM-5.3-Flash-4bit` | ~204 GB | 256 GB | 203,992,076,296 |
| `TensorFold/GLM-5.3-Flash-MLX-2bit-MTP` | ~111 GB | 128 GB | 111,317,859,192 |

`nova download` 的 id 与上表 `org/repo` 相同。两条都标了 `thinking` 与 `tools`。思考和工具标记来自检查点 `chat_template.jinja`。工具 XML 形态是 `<tool_call>{name}<arg_key>…</arg_key><arg_value>…</arg_value></tool_call>`，不是 Nemotron 的 `xmlFunction`。

加载时丢掉视觉权重和 MTP 层（层号大于等于 `num_hidden_layers`，以及 `mtp.*`）。上下文从检查点的 1,048,576 改写为 32,768。内存门在分配前拒绝：4-bit（约 190 GiB）需要 256 GB，混合 2-bit（约 104 GiB）需要 128 GB。带 `vision_config` 的目录仍被发现为文本 LLM。分布式 worker 可传 `skipMemoryGate`。

这次改动没有在 Apple Silicon 上跑通真实权重的生成。数值按 mlx-vlm `glm5_next` 的算子路径实现（limited SwiGLU limit 10、mHC 与 MoE 路由在 float32、KDA linear attention、NoPE MLA）。没有对齐 mlx-vlm 的 Metal kernel。

Text-only catalog rows and a `glm5_next` load path. Thinking and GLM XML tool tags come from the checkpoint chat template. Context is capped at 32,768 tokens. On-device generation with the real checkpoints was not run in this change.

## How to try it

需要已运行的 NovaMLX（Apple Silicon）。推理 API 默认端口 6590。不要下载 zai-org FP8 或 BF16。

4-bit（目录建议 256 GB 统一内存）：

```bash
nova download mlx-community/GLM-5.3-Flash-4bit
nova load mlx-community/GLM-5.3-Flash-4bit
nova chat mlx-community/GLM-5.3-Flash-4bit
```

混合 2-bit（目录建议 128 GB）：把仓库名换成 `TensorFold/GLM-5.3-Flash-MLX-2bit-MTP`。菜单栏 **Downloads** 的 catalog 里两条都带 preview 标记。

短请求：

```bash
curl http://127.0.0.1:6590/v1/chat/completions \
  -H "Authorization: Bearer $NOVA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"mlx-community/GLM-5.3-Flash-4bit","messages":[{"role":"user","content":"用三句话说明什么是混合专家模型。"}]}'
```

内存不足时，加载应直接失败并说明 256 GB 或 128 GB，而不是先分配再 OOM。

## Limits / out of scope

- 图像、视频、Playground 多模态都不在这次发布里。视觉权重被丢掉。
- MTP 推测解码不是产品功能。MTP 权重被忽略。
- 没有 TIE 专家 SSD 流式。
- 不要说 1,048,576 上下文已经可用。实际上限是 32,768。
- 混合 2-bit 质量更差，长代码更不可靠。它不是 orcarouter `GLM-5.3-Flash-MLX` 仓库里的 2bit-lite 子目录（那个子目录不能单独作为 `nova download` 的 id）。
- 真实权重量级生成尚未在本机验证。单元测试覆盖配置解析、内存门、权重重映射，以及一个很小的随机权重前向；完整 `./build.sh` 需要 macOS 与 MLX。

## Suggested video beats

1. 打开 Downloads，指出两条 preview：4-bit 约 204 GB / 256 GB，混合 2-bit 约 111 GB / 128 GB。
2. 终端跑 `nova download` 与 `nova load`，仓库名与目录 id 一致。强调不要下 zai-org FP8/BF16。
3. 一条短文本对话。思考标记来自检查点模板。不要演示图片或视频。
4. 口播限制：上下文 32K 而不是 1M；2-bit 更省内存但质量更差；视觉和 MTP 这次没有。
