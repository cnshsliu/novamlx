# Hunyuan3D-2.1 image-to-3D (Level-1)

**Date:** 2026-10-22 · **Status:** preview · **Scope:** NovaMLX local task-style 3D generation (Level-1)

Internal brief. User-facing page: `docs/features/hunyuan3d.md`.

## What shipped

- Vendored `ZimengXiong/Hunyuan3D-Swift` at `vendors/hunyuan3d-swift` (MIT; repointed to the shared vendored mlx-swift 0.32.3, `unsafeFlags` → `cxxLanguageStandard`). Pure Swift/MLX — no Python subprocess.
- `Hy3DService` (`NovaMLXEngine`): serial one-job-at-a-time queue, `H3VideoJobStatus` states, stable phases `queued/loading/shape/paint/export/done`, cancel polled per denoise step, artifacts `~/.nova/3d/<id>/output.glb`, 24 h TTL. Shape weights resident until unload (`NOVA_HY3D_QUANT=0|4|8`); paint weights built per job and freed (peaks ~25–39 GB).
- API: `POST /v1/3d/generations` (202), `GET /v1/3d/generations/{id}`(+`/content`, `/cancel`), `GET /v1/3d/models`; every job also answers `GET /v1/tasks/{id}` as `task = "3d.generation"` with shared `content`/`cancel`.
- Usage metering for Level-2 (tknet→peer→NovaMLX billing): `usage.meshes = 1`, `usage.size_tier = "shape" | "shape+texture"`, `cost = 0` (local). No billing logic in NovaMLX.
- Catalog: `zimengxiong/hunyuan3d-mlx-shape-small` (3.8 GB), `-shape-large` (4.9 GB), `-paint-large` (8.7 GB), category `threed`, family `hunyuan3d` — MLX conversions of official `tencent/Hunyuan3D-2.1` (Tencent Hunyuan3D Community License). Discovery sniffs shape dirs by `config.yaml` (`depth_single_blocks`/`num_latents`) and paint dirs by `unet/ + dinov2/` without root `config.json`.

## Weight lineage decision

The Swift pipeline loads pre-converted MLX checkpoints, not the official PyTorch safetensors, so catalog ids are the converter's (`zimengxiong/hunyuan3d-mlx-*`), lineage documented in catalog descriptions and the feature page. If Tencent ships official MLX weights (or we fork the converter), swap the catalog ids and keep the API unchanged.
